# アプリ概要

着物・帯・小物のシルエットを組み合わせて表示するアプリの、全体像をまとめたもの。
詳細な型定義やスキーマは含めず、方針レベルにとどめる。

## ユースケース

着物好きな特定の個人が、自身の所有している着物の各アイテムの組み合わせをアプリ上で試す。

他人と共有したり、複数人で使ったりすることは想定しない。そのため権限管理は不要で、
認証はデータをクラウドに置くための最小限のものに限る。

## 扱うデータ

- **アイテム** … 所有している 1 点。カテゴリ、名前、見た目を持つ
- **コーディネート** … 組み合わせ 1 件。名前をつけて保存する。各カテゴリのアイテムを参照する

カテゴリは以下の 7 種で固定とし、増減させない。

着物 / 半襟 / 帯 / 帯揚げ / 帯締め / 帯留め / 羽織

アイテムの見た目は **画像が基本**だが、色だけの登録もできる。羽織を着ていない状態などは、
コーディネート側でそのカテゴリを未選択にすることで表す。

## 画面

| 画面                       | 役割                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| コーディネート             | スワイプで組み合わせを試し、名前をつけて保存する。既存のメイン画面 |
| アイテム一覧               | 所有アイテムをカテゴリ別に見る。登録・編集・削除の起点             |
| アイテム登録               | 写真を撮る / 選ぶ → 背景透過。または色を選ぶ                       |
| 保存したコーディネート一覧 | 保存済みの組み合わせを見る。選ぶとコーディネート画面に反映する     |

## 決めたこと

### 色と画像は分けて持つ

色を単色画像として登録すれば扱いは一本化できるが、採用しない。色をピクセルに変換すると
色そのものの情報が失われ、あとから色で絞り込んだり調整したりできなくなるため。
描画も、色はシルエットの塗りで済むのに対し、画像はシルエットで切り抜く処理が要る。

### データはクラウドに置く

複数端末で見ることはほぼないため同期は要らないが、機種変更でデータを失いたくない。
このアプリの資産は撮り直しの効かない画像なので、手動でのエクスポートに頼らず、
自動的に残る形にする。

同期や競合解決を作り込む必要はなく、素朴な読み書きで足りる。

### 保存先は Supabase にする

認証がダッシュボードで完結すること、Postgres なので中身を直接見られ、
やめたくなったときにデータを取り出しやすいことを理由に選ぶ。

Convex はスキーマから画面まで TypeScript の型が一本で通る点と、リアルタイム同期が
標準で効く点が強いが、後者は単一ユーザーのこのアプリでは活きない。

**着手時にテーブルと Storage バケットの RLS を必ず先に設定する。**
あとから足すと、それまでのデータが公開されていた期間ができてしまう。
